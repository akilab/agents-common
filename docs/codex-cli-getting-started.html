CODEX CLI / FIRST STEPS

ターミナルで始める
Codex CLI

Codex CLI は、作業したいリポジトリのフォルダで起動し、会話しながらコードを読ませ、変更・検証・レビューを進めるための対話型ツールです。最初は小さな確認から始めます。

最終確認: 2026-08-09 · 実行前に表示される権限確認を読んで承認する
始める依頼する進め方コマンド安全に使う
01

まず、作業したいフォルダで起動する

Codex CLIは、起動した場所を作業対象として扱います。 ホームフォルダで起動するのではなく、対象リポジトリへ移動してから起動します。

POWERSHELL

起動

cd D:\Projects\my-project
codex

初回はログイン画面が開くことがあります。ChatGPTアカウントで進めます。ログイン状態だけを確認するなら codex login status を使います。

START SMALL

最初の一言

このリポジトリをまだ変更せずに確認して、
構成・起動方法・テスト方法を短く説明してください。

最初に「変更せずに」と明示すると、環境の把握を落ち着いて始められます。

02

依頼は「目的・範囲・確認方法」を添える

調査する

「認証処理がどのファイルから呼ばれるか調べて、関連ファイルと流れを説明してください。変更はしないでください。」

修正する

「この画面の余白を16pxに統一してください。関係ない見た目は変えず、最後にlintを実行してください。」

原因を探す

「このエラーを再現し、原因候補を優先順位付きで示してください。修正前に方針を説明してください。」

いきなり「全部直して」より、対象・触らない範囲・終わりの条件を一つずつ足すと、結果をレビューしやすくなります。

03

普段の進め方

1. 読ませる

構成、既存の指示、テスト方法を確認してもらう。初めは読み取りだけの依頼が安心です。

2. 方針を決める

変更が大きいときは、実装前に「方針と変更対象を説明して」と頼みます。

3. 変更を承認する

Codexがコマンドや変更の承認を求めたら、対象・影響・理由を確認してから許可します。

4. 検証する

テスト・lint・ビルドなど、そのプロジェクトに合う確認を依頼します。

5. 差分を読む

/diff で差分を見て、必要なら「この変更の意図を説明して」と続けます。

6. レビューする

/review で作業ツリーのレビューを依頼し、指摘とテスト不足を確認します。

04

最初に覚えるコマンド

/status

モデル、承認方針、書き込み可能な場所、現在のコンテキスト使用量を確認する。

/diff

Codexや自分が行った未コミット変更を確認する。

/review

現在の作業ツリーをレビューしてもらう。実装後の確認に使う。

/compact

長くなった会話を要約して、重要な要点を残したままコンテキストを空ける。

/new

表示を残したまま新しいチャットを開始する。作業テーマを切り替えるときに便利。

/clear

ターミナル表示と会話の両方を新しくする。Ctrl + L は表示だけを消し、会話は残る。

/resume

保存済みの会話を選び、以前の続きから再開する。

/quit

Codex CLIを終了する。

/ を入力すると、その時点で使えるコマンド候補を一覧できます。全コマンドを覚える必要はありません。

05

最初は安全側で使う

DO

おすすめ

  • まずは調査・説明・レビューなど、変更を伴わない依頼から始める。
  • 変更後は /diff とテスト結果を確認する。
  • 不明な承認は、何を実行するか説明させてから判断する。
  • リポジトリのルールは AGENTS.md に残す。
AVOID

避けること

  • --yolo など、承認とサンドボックスを一括で無効にするオプションを普段使いしない。
  • 内容を確認せずに、削除・一括置換・外部公開の承認をしない。
  • 既存の AGENTS.md があるリポジトリで、確認せずに /init を実行しない。
